# Development

Build and run the C++ test suites:

```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Debug
cmake --build build -j2
ctest --test-dir build --output-on-failure
```

Assertions remain enabled in release test builds: the test harness does not rely
on C `assert`. CI covers GCC (including AddressSanitizer/UBSan), Apple Clang, and
MSVC. Use `-DNAVAL_SDK_SANITIZERS=ON` to instrument a local GCC/Clang build.

For the loopback network/TLS suite, install Python 3.11+ and `websockets==15.0.1`
in a virtual environment before configuring. CMake discovers it via
`Python3_EXECUTABLE`; if absent, the C++ tests still run. TLS tests also require
the `openssl` command. Test tokens, keys, and certificates are synthetic and temporary.

```sh
python -m venv .venv
. .venv/bin/activate
python -m pip install websockets==15.0.1
cmake -S . -B build -DPython3_EXECUTABLE="$VIRTUAL_ENV/bin/python"
cmake --build build -j2
ctest --test-dir build --output-on-failure
```

## Python comparison fixtures

`tests/fixtures/python_parity.json` contains 250 deterministic geometry cases and
160 multi-tick tactical snapshots generated by the original Python implementation.
Ordinary C++ tests need neither Python nor a network to validate these fixtures.
Regenerate only when deliberately changing the reference behavior:

```sh
git clone https://github.com/wilfredluijk/battle-sim-python-sdk.git /tmp/naval-python-reference
git -C /tmp/naval-python-reference checkout 816fa9baba75c7294561a6f111aa2735f4bbdd01
PYTHONPATH=/tmp/naval-python-reference python tools/generate_python_parity.py
```

The generator needs the Python SDK's `websockets` dependency. Preserve the source
commit and original license when updating fixtures.

## Real-server integration

Build the Rust battle-sim server separately. The test starts a temporary local
server with synthetic admin credentials, runs two C++ bots, updates configuration,
plays two rounds, and verifies telemetry and recording/replay. It never contacts
a production endpoint.

```sh
BATTLE_SIM_SERVER=/absolute/path/to/naval-server \
  python tests/rust_server_test.py build/tests/transport_client
```

Setting that environment variable before CMake configuration also registers the
test with CTest. Keep it set while running CTest. The test requires a server with
the configuration and own-ship telemetry capabilities used by the reference SDK.

## Packaging

`cmake --install` exports `naval_sdk::naval_sdk`. Verify installation with
`tests/consumer`, including static-library transitive link dependencies. Avoid
checking in builds, environment files, recordings, credentials, or dependency caches.
The release is distributed as source through GitHub; no external package-registry
account is required.
